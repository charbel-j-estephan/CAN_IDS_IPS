0. Golden rules

Read these once. Breaking one of them is how boards die or results get wrong.

Never put 5 V on FPGA header pin 1. Pin 11 is 5 V, pin 1 is CAN RX. The RX line goes through the resistor divider only. Do not move any wire on the DE10 Lite header unless this guide says so.
Never share or copy anything from updatable fpgas\quartus\, keys\ or Desktop\master.key. They hold the board's secret key. Don't email them, don't put them on a USB stick, don't zip them.
Close every Arduino Serial Monitor before any test. An open monitor blocks the COM port and the run fails with "Access is denied".
Unplug the USB before you move a wire or a jumper. Ground goes on first and comes off last.
If a result does not match the expected box, stop. Write what you saw in the notes box of that test, take a photo of the screen and the board LEDs, and message Charbel before going on. A wrong number is still useful. A guessed number is not.

3. Build and program the FPGA

40 minonce The Verilog has a new switch, SW2. The FPGA needs a fresh build to get it.

What changed in the design. When SW2 is up, the FPGA destroys a frame only if all five trees vote attack, or if the ID is one the car never sends. A 3 or 4 of 5 verdict becomes an alert only. This removes every false flag in the dataset while still stopping all DoS, gear and RPM attacks. It was already checked in simulation: bit for bit the same as Python on 675,167 distinct frames, and attacks still destroyed on a simulated bus.
  5. program_fpga.bat
Fmax under 50 MHz, or errors? Stop and send Charbel a screenshot of the report. Don't program a design that misses timing.

T6. Live model update (the headline)

25 min The FPGA's circuit stays the same. Only its model changes, sent as a signed, scrambled file through the STM32 over SPI. No Quartus, no USB Blaster.

The STM32 changes job here. It stops being a CAN detector and becomes the update tool. The demo script handles the jumper steps and waits for you at each one. Follow its screen exactly: shield off, BT0 jumper to 3V3, press RST, Enter. Then BT0 off 3V3, shield back on, RST, Enter.

T8. Power, the easy way

20 minPC only, no cutting, nothing to buy Quartus estimates the FPGA's power from the compiled design. You do it twice, once per design, with the same settings, so the paper can compare them.

What the paper needs. Four numbers per design: total, core dynamic, core static and I/O power. That is all. It will be labeled "estimated by Quartus", which reviewers accept.

Design 1: the updatable design (already compiled in section 3)

Design 2: the hardcoded design

Optional: a real reading, only if the lab lends you a USB power meter

A USB power meter is a small dongle that plugs between the USB cable and the board and shows volts and milliamps. No cutting. If the electronics lab has one:

Never cut or strip a cable, and never power the board from a header pin. If there is no USB meter, skip this part: the Quartus numbers are enough.

10. If something goes wrong

What you seeWhat to do
"Could not find exactly one sender and one receiver"A USB cable, or a Serial Monitor is open. Close the Arduino IDE, replug the ESP32s, run again.
Link check FAILEDA bus wire or terminator. Power off, check CANH to CANL is about 60 Ω, check no CANH is on a CANL rail.
"needs attack_sender version 2"The attacker has the old program. Stop, ask Charbel to upload esp32\attack_sender.
Attack frames arrive in T1 to T3SW0 is down, or the wires on FPGA pins 1 and 2. Check LEDR9 is on.
LEDR0 never blinksThe FPGA hears nothing: its CAN shield, the divider on pin 1, or the board lost its design (LEDR4/5 both off: run program_fpga.bat again).
"The FPGA does not answer (all FF)"Push both SPI plugs fully in. Unplug both USB cables, plug the DE10 Lite first, then the STM32.
Update "port locked" (LEDR6 on)Three bad stamps since power on. Unplug the DE10 Lite USB and plug it back.
STM32 shows up as "STM32 BOOTLOADER"It started with BOOT0 high. BT0 off 3V3, shield on, RST, run the step again.
"The replay did not finish"Read the lines above it. Usually a USB cable or an open Serial Monitor.
Quartus compile fails on device_key.vhThe board key file is missing. Stop, Charbel makes it (it needs master.key).
Anything elseStop. Photo of the screen and the LEDs. Message Charbel. Don't improvise.
